01 What this PR does

PR D4 is the final layer of the frontend SPA stack. It adds the four page-level components and the upload form, and it replaces the placeholder App.tsx (which was committed as a one-liner stub in C1) with the real React Router routing tree.

Every earlier PR built a foundation layer: C1 added the project scaffold, C2 added pure library functions, D1 added display-only components, D2 added the specimen/variant table tier, D3 added the classification panel. D4 is the integration layer: it imports from all of those, composes them into pages, and hands the result to React Router.

Design principle

Pages in this codebase are deliberately thin wrappers. Each page does exactly three things: fetch data from the API, hold that data in local state, and pass it as props to child components. No business logic lives in pages. This makes pages easy to test, easy to replace, and impossible to misuse as a "God component" that mixes display with data-mutation logic.

No business logic in pages

Pages import nothing from classification-engine.ts, display-utils.ts, or pipeline-config.ts directly. All formatting and scoring logic lives in the child components (D1–D3). Pages only call the API and pass raw data down.
