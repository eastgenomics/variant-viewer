24 PatientDetailPage — useEffect with NaN guard and Promise.all

PatientDetailPage.tsx — useEffect callback
useEffect callback PatientDetailPage.tsx · fetch on mount/route change 
useEffect(() => {                                              // ①
  if (!id || isNaN(Number(id))) {                              // ②
    setNotFound(true);
    setLoading(false);
    return;
  }
  const numericId = Number(id);                               // ③
  getPatient(numericId)
    .then(async (p) => {
      setPatient(p);
      const details = await Promise.all(                      // ④
        p.samples.map((s) => getSample(s.id))
      );
      setSamples(details);
    })
    .catch((e) => {                                           // ⑤
      if (e instanceof ApiError && e.status === 404) setNotFound(true);
      else setError(e instanceof ApiError ? e.detail : "Failed to load");
    })
    .finally(() => setLoading(false));
}, [id]);                                                      // ⑥
①
useEffect with dependency array. The callback runs once on mount, and again any time a value in the dependency array changes. Here the dependency is [id] — so the effect re-runs whenever the user navigates to a different patient's URL, refreshing the data without a full page reload.
②
NaN guard. useParams() always returns a string. Number("abc") evaluates to NaN. If the guard were absent, getPatient(NaN) would call GET /api/patients/NaN — a 404 at best, an unhandled exception at worst. The guard also covers undefined (the route would need to be misconfigured, but defensive checks cost nothing). Setting notFound = true causes the component to return <Navigate to="/" replace /> on the next render.
③
Local numeric variable rather than patientId. The outer scope has const patientId = Number(id) declared before the effect. A local numericId is used inside the effect instead, because calling Number(id) again makes the conversion explicit and avoids capturing a potentially stale closure value of patientId if the component re-renders between the effect setup and its execution.
④
Promise.all for parallel specimen fetches. p.samples is an array of SampleSummary objects (lightweight — id, name, status). <SpecimenCard> needs the full SampleDetail (variant count, tissue, sequencing date). Promise.all fires all getSample() calls simultaneously. If the patient has 3 specimens, this takes as long as the slowest single fetch rather than 3× the average. If any fetch rejects, the whole Promise.all rejects and the .catch block handles it.
⑤
Differentiated error handling. A 404 means the patient does not exist (or the id was wrong) — so the component redirects silently rather than showing a red error banner. Any other ApiError (e.g. 500 server error) surfaces as a banner with the backend's detail message. Non-ApiError exceptions (e.g. a network failure before the server responds) show a generic fallback string.
⑥
Why [id] not [patientId]. patientId is Number(id). If id is "abc", patientId is NaN. In JavaScript, NaN !== NaN — so React's dependency check would always consider patientId "changed" and re-fire the effect on every render, creating an infinite loop. The raw string id changes only when the URL actually changes.

25 ClassificationPage — case_type runtime validation

ClassificationPage.tsx — ClassificationPanel caseType prop
caseType prop derivation ClassificationPage.tsx · JSX section 
<ClassificationPanel
  variantId={variant.id}
  caseType={                                                    // ①
    variant.case_type === "somatic" ? "somatic" : "germline"   // ②
  }
  gene={variant.gene}
  initialClassification={
    variant.active_classification                              // ③
      ? {
          id: variant.active_classification.id,
          framework: variant.active_classification.framework,
          framework_version: variant.active_classification.framework_version,
          score: variant.active_classification.score,
          classification: variant.active_classification.classification,
          locked_at: variant.active_classification.locked_at,
          locked_by: variant.active_classification.locked_by,
        }
      : null
  }
  initialCriteria={variant.active_classification?.criteria ?? []}  // ④
/>
①
Why not as "germline" | "somatic"? VariantDetailResponse.case_type is typed as string in api.ts (because the backend returns any string from the database column). ClassificationPanel requires "germline" | "somatic" exactly. A type cast like variant.case_type as "germline" | "somatic" would silence TypeScript but do nothing at runtime — if the database ever contained an unexpected value, it would propagate silently into the classification engine.
②
Explicit runtime guard with a safe default. The ternary checks for the known alternative value ("somatic") explicitly. Anything that is not "somatic" — including unexpected future values like "mosaic" or null — defaults to "germline". This is correct for the current data model (only two valid values) and safe for future schema changes: new values will quietly default rather than causing a crash.
③
Splitting active_classification from criteria. ClassificationPanel takes initialClassification (the classification metadata: id, framework, score, classification, locked_at, locked_by) as a separate prop from initialCriteria (the array of individual criterion states). The API response nests criteria inside active_classification, but the panel separates them for internal state management — it initialises criterion state from the criteria array separately from the classification lock state. The page therefore destructures the nested response into two distinct props rather than passing active_classification directly.
④
Optional chaining with fallback. variant.active_classification?.criteria ?? [] returns the criteria array if a classification exists, or an empty array if active_classification is null (unclassified variant). The ?? operator (nullish coalescing) returns the right-hand side only if the left-hand side is null or undefined — not for falsy values like empty strings or zero.

26 handleDevUpload — FormData field mapping

UploadForm.tsx — handleDevUpload
handleDevUpload UploadForm.tsx · dev path only 
async function handleDevUpload() {
  setPhase("ingesting");
  setProgress("Ingesting VCF\u2026");

  const fd = new FormData();
  fd.append("vcf", file!);                                     // ①
  fd.append("lab_number", labNumber.trim());                   // ②
  fd.append("specimen_name", sampleName.trim() || file!.name); // ③
  fd.append("case_type", caseType);
  if (pipelineKey) fd.append("pipeline_key", pipelineKey);    // ④
  if (sequencingDate) fd.append("sequencing_date", sequencingDate);

  const resp = await fetch("/api/ingest-direct", {
    method: "POST",
    headers: authHeaders(),                                    // ⑤
    body: fd,
  });
  if (!resp.ok) {                                              // ⑥
    let detail = `HTTP ${resp.status}`;
    try { detail = (await resp.json()).detail ?? detail; } catch { /* ignore */ }
    throw new Error(detail);
  }
  const body = await resp.json();                             // ⑦
  setPhase("done");
  setProgress(`Sample ${body.sample_id} ingested successfully.`);
}
①
File part named "vcf". The backend declares vcf: UploadFile = File(...). FastAPI matches the parameter by the multipart part name — if this were fd.append("file", ...) or fd.append("upload", ...), the backend would return 422 "field required: vcf".
②
.trim() on lab_number. Accidental leading/trailing spaces in a lab number would create a patient with a whitespace-prefixed MRN that cannot be found by a clean lookup. The backend does not trim inputs — trimming at the point of form submission is the right place.
③
Specimen name fallback. sampleName.trim() || file!.name — if the user leaves the specimen name blank, the VCF filename is used as the specimen name. This mirrors how the production ingest Lambda behaves when the manifest does not specify a sample name.
④
Optional fields only appended when truthy. pipeline_key and sequencing_date are optional on the backend (str | None and date | None). Appending an empty string would be treated as a non-None value by FastAPI. The if (pipelineKey) guard ensures the field is absent from the request when not set, so the backend uses its default.
⑤
authHeaders() returns only {X-API-Key: ...} — no Content-Type. This is critical: when the browser sends a FormData body, it automatically sets Content-Type: multipart/form-data; boundary=----... including the unique boundary string. Manually setting Content-Type would override this and omit the boundary, making the request unparseable by the server.
⑥
Check resp.ok before reading body. An earlier version called resp.json() unconditionally and then checked resp.ok. The problem: if the error response has a non-JSON body (e.g. a 413 Too Large response from nginx before the request reaches FastAPI), resp.json() throws, and the actual status code and detail are lost. Checking resp.ok first, then attempting to parse the error body in a try/catch, surfaces the best available error message.
⑦
resp.json() only reached on success. The response body is {"sample_id": 42, "message": "Ingested successfully"}. The function uses body.sample_id in the success message. Note that body.message is also available but unused — the progress message is constructed inline instead.

27 handleProdUpload — the 4-step S3 sequence

UploadForm.tsx — handleProdUpload
handleProdUpload UploadForm.tsx · production path only 
async function handleProdUpload() {
  setPhase("uploading");
  setProgress("Requesting upload URLs\u2026");

  const urlResp = await getUploadUrl({                         // ①
    vcf_filename: file!.name,
  });

  setProgress("Uploading VCF to S3\u2026");
  const vcfUploadResp = await fetch(urlResp.vcf_url, {        // ②
    method: "PUT",
    body: file!,
    headers: { "Content-Type": "application/octet-stream" },
  });
  if (!vcfUploadResp.ok) throw new Error("VCF S3 upload failed");

  setProgress("Uploading manifest\u2026");
  const manifest = buildManifest({                             // ③
    labNumber: labNumber.trim(),
    specimenName: sampleName.trim() || file!.name,
    caseType,
    pipelineKey: pipelineKey || null,
    sequencingDate: sequencingDate || null,
    vcfFilename: file!.name,
  });
  const manifestResp = await fetch(urlResp.manifest_url, {    // ④
    method: "PUT",
    body: JSON.stringify(manifest),
    headers: { "Content-Type": "application/json" },
  });
  if (!manifestResp.ok) throw new Error("Manifest S3 upload failed");

  setPhase("ingesting");
  setProgress("Triggering ingest\u2026");
  const result = await ingestSample({                          // ⑤
    vcf_s3_key: urlResp.vcf_key,
    user_id: (import.meta.env.VITE_USER_ID as string | undefined) ?? "analyst",
  });
  setPhase("done");
  setProgress(`Sample ${result.sample_id} ingested successfully.`);
}
①
Field is vcf_filename, not filename. The backend UploadUrlRequest Pydantic model has a single field named vcf_filename. An earlier version of this code used {filename: file.name} — this would cause a FastAPI 422 validation error: "field required: vcf_filename". The getUploadUrl function in api.ts accepts UploadUrlParams which enforces the correct shape at compile time.
②
Direct PUT to S3 presigned URL. The presigned URL already contains the AWS authentication signature as query parameters. The fetch sends the raw file bytes as the body with Content-Type: application/octet-stream. No additional auth headers are sent to S3 — adding them would likely cause a signature mismatch error. The response has no JSON body; checking resp.ok is sufficient.
③
buildManifest must be called before the ingest trigger. The manifest is a sidecar JSON file the backend Lambda downloads when processing the ingest. If ingestSample were called before buildManifest and its PUT, the Lambda might start processing before the manifest exists — a race condition that would cause a failed ingest. The await chain enforces the correct ordering.
④
Manifest PUT uses JSON.stringify(manifest) as body. Unlike the VCF upload (raw binary), the manifest is a JSON document. The backend Lambda calls manifest_path.read_text() and then json.loads(), so the body must be a valid JSON string, not a plain JS object. Content-Type: application/json matches what S3 stores and what the Lambda reads.
⑤
vcf_s3_key is the S3 key, not the presigned URL. ingestSample sends {vcf_s3_key: urlResp.vcf_key} — the S3 object key like runs/2026-05-21/sample.vcf.gz. The backend uses this key to download the file from S3 using its own AWS credentials. Sending the presigned URL instead would not work — presigned URLs expire and contain signature parameters the backend would not know how to use for a download.

28 handleSubmit — isDev gate and phase state machine

UploadForm.tsx — handleSubmit
handleSubmit UploadForm.tsx · form onSubmit handler 
async function handleSubmit(e: React.FormEvent) {
  e.preventDefault();                                           // ①
  setError(null);
  setPhase("idle");                                             // ②

  if (!labNumber.trim()) {                                      // ③
    setError("Lab record number is required.");
    return;
  }
  if (!file) {
    setError("Please select a VCF file.");
    return;
  }

  try {
    const isDev =                                               // ④
      import.meta.env.DEV || import.meta.env.VITE_APP_ENV === "development";
    if (isDev) {
      await handleDevUpload();
    } else {
      await handleProdUpload();
    }
  } catch (err) {                                               // ⑤
    setPhase("error");
    setError(err instanceof Error ? err.message : "Upload failed.");
  }
}
①
e.preventDefault() prevents native form submission. Without this, clicking "Upload VCF" would cause a full-page HTTP GET or POST to the current URL — the default browser form behaviour. React forms always need this call to keep the interaction inside the SPA.
②
Phase reset before validation. setPhase("idle") runs on every submit attempt, including retries. If it were absent, a user who corrected an error and resubmitted would find the phase still set to "error" from the previous attempt — and the isUploading = phase === "uploading" || phase === "ingesting" flag might behave unexpectedly. Resetting first guarantees a clean state machine before each attempt.
③
Client-side validation runs before the isDev check. Validation errors are 100% client-side and do not depend on which upload path will be used. Placing them before the path selection keeps the function's intent clear: validate everything first, then decide how to upload. The return statements short-circuit the function before any async work begins.
④
isDev evaluated inside the function, not at module load. import.meta.env.DEV is baked in at build time by Vite — it is a boolean constant in the compiled bundle. However, import.meta.env.VITE_APP_ENV can be controlled via build args. Evaluating isDev inside handleSubmit (at call time) rather than as a module-level constant means test code can stub import.meta.env without reloading the module, and the check reflects any last-moment env changes during testing.
⑤
Single catch for both upload paths. Both handleDevUpload and handleProdUpload are designed to throw on any failure rather than call setError themselves. This keeps those functions focused on their happy path and centralises all error state management here. The check err instanceof Error ? err.message : "Upload failed." guards against cases where something other than an Error object is thrown (e.g. a rejected Promise with a raw string).
