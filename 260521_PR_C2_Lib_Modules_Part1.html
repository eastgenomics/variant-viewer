01 What PR C2 adds

PR C2 is the second of eight PRs in the variant-viewer frontend series. It adds the pure function layer — five TypeScript modules that contain all the data-transformation, API-communication, and domain-logic code. No React components, no DOM interaction, no side effects from the perspective of the caller. Everything in this PR can be tested with plain Vitest unit tests without mounting any component tree.

The modules sit between the scaffold (PR C1, which set up Vite/React/Tailwind) and the visual components (PRs D1–D4, which import these modules). Getting the lib layer right first means the components can be written without duplicating logic or hard-coding formatting rules.

Why pure functions first?

Pure functions are the easiest code to test and the hardest to get wrong silently. By landing the classification engine, formatters, and API client before any component code, we know that if a component displays the wrong classification it is a component bug — the engine itself is validated by its golden-case tests against the Python backend.

02 Module architecture

The five modules are deliberately layered so that dependencies flow in one direction only. api.ts is the widest dependency — every component that talks to the server imports from it. classification-engine.ts is self-contained except for the bundled JSON config files it imports at module load time.

03 Data flow

The modules serve three distinct data flows in the application. Understanding which flow each module belongs to helps locate the right file when debugging a problem.

FlowDirectionModules involvedExample
Fetch & display Backend JSON → TypeScript object → formatted string api.ts → display-utils.ts getVariant(id) returns a VariantDetailResponse; formatGnomadAf(v.gnomad_af) renders it
Classification Applied criteria array → score + label classification-engine.ts (reads JSON config) classify(criteria, "acgs_snv", rules) → {score:9, classification:"Likely_Pathogenic"}
Upload Form fields → FHIR Bundle JSON → S3 PUT fhir-manifest.ts, then api.ts for getUploadUrl() and ingestSample() buildManifest({labNumber, ...}) → JSON string PUT to presigned URL

04 External dependencies

All dependencies in this PR are already present in the project. The lib modules introduce no new npm packages. They rely only on browser globals (fetch, URL), TypeScript's type system, and JSON files bundled at build time by Vite.

URL (browser global)fhir-manifest.ts (not directly), api.ts (URLSearchParams)Building query strings for paginated list endpointsN/A — browser global
No acgs-snv-criteria.json import in classification-engine.ts

The classification engine does not import the criteria JSON files. It receives combinationRules as a parameter — the caller (ClassificationPanel in PR D3) loads the JSON and passes the relevant array in. This keeps the engine pure and independently testable without bundled JSON.
