01 What this PR does

PR D1 is the fourth in a chain of eight stacked pull requests that together build the variant-viewer React SPA. It adds the first layer of visible UI: five stateless display components that render read-only information. No data fetching, no side effects, and (with one exception) no mutable state — these are pure render functions that receive data as props and paint the screen.

The one exception is PatientListTable, which inlines a DeletePatientButton function component. That button manages a simple two-step confirmation state: idle → confirming → (success or error). It is the only piece of interactive logic in this PR.

Invariant 1 — PII exclusion

None of these components ever renders patient.name, nhs_number, or date of birth. PatientHeader intentionally uses Pick<PatientDetailResponse, "id" | "lab_number"> so the TypeScript type does not even include name. The test suite explicitly asserts that the patient name is not in the document. This is a deliberate clinical safety constraint — only the MRN (lab_number) is shown as a patient identifier.

Migration 004 — dob removed

An earlier version of this code displayed Year of Birth (YOB) via a formatYearOfBirth(dob) helper. Migration 004 (migrations/004_remove_patient_dob.sql) dropped the dob column from the patients table on UK GDPR data-minimisation grounds. The YOB column, the dob field on PatientSummary, and the formatYearOfBirth call were all removed. The test fixture comments // dob removed — migration 004 to explain why the field is absent despite being visible in earlier commit history.

What the components do together

These five components are the "read layer" of the patient list page. A user who loads the application sees:

  1. The Navbar across the top of every page — links to Cases and Upload VCF.
  2. The PatientListTable as the main content — one row per patient, with MRN, specimen count, latest specimen name, pipeline, workflow status badge, ingested date, a View link, and a Delete action.
  3. Within each row, a WorkflowBadge coloured according to workflow status.
  4. On the patient detail page, a PatientHeader showing the MRN as a heading.
  5. On the classification page (later PRs), ClassificationBadge appears in the variant table to indicate classification outcome.

02 Component architecture

All five components are purely functional — they accept props, return JSX, and do nothing else on first render. The one interactive element (DeletePatientButton) is defined as an inner function inside PatientListTable.tsx rather than a separate file, because it is only used by that one parent.

File structure

Each component lives in its own .tsx file under frontend/src/components/. Each has a companion test file in frontend/src/tests/. The exception is DeletePatientButton, which is defined as a private inner function at the top of PatientListTable.tsx and is not separately exported.

No imports between components in this PR

PatientListTable imports WorkflowBadge. That is the only inter-component dependency within this PR. Everything else imports only from ../lib/api (for TypeScript types) or from react-router-dom (for the Link component).
