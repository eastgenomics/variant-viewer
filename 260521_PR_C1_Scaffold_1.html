01 What PR C1 does

PR C1 is the first frontend PR in the stacked series. It adds everything needed to build, test, and containerise a React SPA — but none of the actual application code. Every component file, page file, and library module is either absent or a one-line placeholder at this point. The application logic lands in PRs C2 through D4.

Think of this PR as laying a factory floor before any machinery arrives. After merging C1 you can run npm run build and get a valid dist/ bundle; run npm test and get zero tests (cleanly, without error); and run docker build to get a working nginx image that serves the empty shell with correct SPA routing.

Scope boundary

PR C1 contains no business logic. The App.tsx is a placeholder that renders nothing. All real components, pages, and library functions are introduced in PRs C2–D4. Reviewing C1 means asking: does the build wiring make sense? Is the Docker image correct? Are the Tailwind classes right?

03 Data flow

Three separate file categories flow through the build at different points.

Important: JSON bundling

The criteria JSON files (acgs-snv-criteria.json, svig-criteria.json, canvig-gene-mtaf.json) are bundled into the JS at build time via resolveJsonModule: true in tsconfig. They are not fetched at runtime. This means any change to the criteria requires a rebuild and redeployment — but it also means the classification engine works offline with zero network latency.

Note: no @vitest/jsdom

Some tutorials recommend @vitest/jsdom but that package does not exist — the correct package is jsdom. The environment: "jsdom" setting in vite.config.ts tells Vitest to use the installed jsdom package automatically.
